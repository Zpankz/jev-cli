Find one thing in an image; returns the four edges of a box around it (experimental)

When to use:
Use `jev box` to find where one thing is in an image: the answer is the four edges of a box around
it, as fractions of the image's width and height. Experimental (TypeSafe calls it dreamer-ready): it
needs Jev 1.14 and sends `TypeSafe-Danger-Zone-Images: true`. There is no not-found answer, so ask
`jev noul` (or `jev eval` with a noul beside the box) whether the thing is there at all. Use `jev
eval` to locate several things in one call.

Input:
QUESTION in plain words naming the thing and the image, such as "the mug in `photo`", or
--instructions-file. The image is --image NAME=PATH (PNG or JPEG, 280 to 1568 px a side); repeat for
more images, and --state-file may add an object state beside them. The model is --model, else
TYPESAFE_DEFAULT_MODEL, else the profile, else `jev-1.14.0` (not `jev-latest`, whose Jev 1.13 cannot
answer a box).

Output:
`box` (`top`, `bottom`, `left`, `right`, each 0 to 1 from the top left), `confidence` (or null),
then `model`, `requested_model`, `usage`, `cost_usd` (an estimate), `request_id`, `latency_ms`, and
`gate` when --min-confidence was used. `--field box` prints the edges as JSON.

Usage: jev box [OPTIONS] [QUESTION]

Arguments:
  [QUESTION]
          The question, in plain words

Options:
      --instructions-file <FILE>
          Structured instructions (JSON or YAML: `what`, `not_for`, `examples`, ...) instead of
          QUESTION

  -h, --help
          Print help (see a summary with '-h')

Gating:
      --min-confidence <C>
          Exit 10 when the confidence is below this

State:
      --state <TEXT>
          The state to evaluate, as text (`-` is not stdin here: use --state-file -)

      --state-file <PATH>
          Read the state from a file, or from stdin with `-`

      --state-format <FORMAT>
          How to read the state: `json` sends an object or array, `text` one string

          Possible values:
          - auto: JSON for a `.json` file, text for everything else
          - text: Send the content as one string
          - json: Parse the content as JSON and send the object or array

          [default: auto]

      --image <NAME=PATH>
          Attach a PNG or JPEG under NAME in an object state, so a question can say `NAME`; repeat
          for each image (experimental; Jev 1.13 and 1.14)

      --asset <REF=PATH>
          Attach a PNG or JPEG as an asset keyed by REF, without naming it in the state; write REF
          in a question's instructions or criteria (e.g. a choice option shown as a picture); repeat

Sending:
      --dry-run
          Validate, print the exact request body and a size estimate, and send nothing

      --strict
          Treat validation warnings as errors

      --skip-size-check
          Skip the offline estimate of the request's size

      --warn-unpinned
          Remind me on stderr to pin a versioned model id when the request used an alias

      --raw
          Print the API response body exactly as received, ignoring --output

Global options:
      --profile <NAME>
          Named profile to use (its API key, base URL and defaults) [env: `JEV_PROFILE`]

  -o, --output <FORMAT>
          Output format [default: table on a terminal, json when piped] [env: `JEV_OUTPUT`]

          Possible values:
          - table: Readable text for a person at a terminal
          - json:  One pretty-printed JSON document. The default when stdout is not a terminal
          - yaml:  One YAML document
          - jsonl: Compact JSON, one record per line

      --field <PATH>
          Print one raw value from the output, e.g. `answers.is_urgent.noul`

      --model <MODEL>
          Model alias or versioned id, e.g. `jev-latest` or `jev-1.13.0`

      --base-url <URL>
          API root [default: https://api.typesafe.ai]

      --timeout <DURATION>
          Time allowed per attempt, e.g. `30`, `30s`, `500ms` or `2m` [default: 30s]

      --max-retries <N>
          Retries after the first attempt; 0 disables retrying [default: 2]

      --long-context
          Experimental: send `TypeSafe-Danger-Zone-Long-Context: true`, raising both context budgets
          to 262k tokens; slower and less accurate [env: `JEV_LONG_CONTEXT`]

      --compress
          Gzip request bodies of 1 KiB or more; saves upload time on large states and images [env:
          `JEV_COMPRESS`]

      --no-input
          Never ask for input; fail with an error naming the flag to use instead

          [env: JEV_NO_INPUT=]

      --no-color
          Disable colour (also honours the `NO_COLOR` environment variable)

      --ascii
          Use only ASCII characters in human-readable output

      --insecure-allow-http
          Allow a plain http:// base URL to a host other than localhost (the API key travels
          unencrypted)

      --debug-bodies
          Log request and response bodies with -v; `state` may contain sensitive data

  -q, --quiet
          Print errors only; suppress notices and warnings on stderr

  -v, --verbose...
          Log to stderr; repeat for more (-v requests and retries, -vv everything)

Exit codes:
  0    success, and the condition holds (or no gate was given)
  2    usage or validation error; nothing was sent
  3    no API key, or the API refused it
  4    the API rejected the request
  5    rate limited or overloaded, after retries
  6    network failure, timeout or server error, after retries
  10   evaluated, and --min-confidence does not hold (never an error)

Examples:
  # Find a mug in a photo; the edges are fractions of the image
  jev box "the coffee mug in `photo`" --image photo=kitchen.jpg

  # Only the edges, as JSON, for a script that crops the image
  jev box "the signature in `scan`" --image scan=form.png --field box

  # Exit 10 unless the model is fairly sure of the box
  jev box "the person at the door in `cam`" --image cam=door.jpg \
      --model jev-1.14.0 --min-confidence 0.6
